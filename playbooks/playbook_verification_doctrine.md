# Verification doctrine — portable core (distilled 2026-07-12)

Every rule here is a scar, not a theory. Apply in any project, any domain.

1. **No author reviews their own work** — human or agent, including the strategist reviewing its own briefs. Independent verification = a FRESH-context agent that defaults every finding to "not real" and must reproduce it from source. (20/20 confirmed on the first full-week audit run this way; several verifiers explicitly disregarded the finder and re-derived.)
2. **Grep counts lie.** A hit inside another word (`sha`**`red`**, `th`**`re`**`atened`) inflates counts — caught twice inflating leak counts. Read each hit's surrounding context; prefer answer-specific fragments over generic terms; never trust the number alone.
3. **Runtime > code-read for binary gates.** Serve the real thing and grep the actual output (HTML/RSC/JSON/API response), not the source. Always run a **negative control** — prove the grep CAN find the pattern where it legitimately exists, or a clean result is indistinguishable from a broken grep.
4. **Evidence or it didn't happen.** "I checked, it's clean" is not verification — paste the commands and their output in the completion note. Write completion notes for a SKEPTIC: name what you did NOT test, flag every shortcut.
5. **Test, don't assume** — never skip a smoke test because "the underlying infrastructure is prod-tested." The wiring is new even when the mechanism isn't; bugs live in wiring.
6. **Escalate, don't grind.** Two failed fix rounds — or trading a failure for its opposite — means the APPROACH is wrong. Stop and escalate; grinding burns context and entrenches the wrong frame.
7. **Faster, more confident models raise the stakes.** Top-tier models produce plausible-but-wrong output at higher speed and higher confidence — verification matters MORE as capability rises, not less.
8. **Re-derive the premise, not just the answer.** Count-right-mechanism-wrong is a real failure class; a fix justified by a stale premise is wrong even when its arithmetic checks out. Re-grep the current source before trusting any premise inherited from an earlier session.
9. **Verify external facts; recall internal ones.** Training data ages — APIs, pricing, SDK capabilities get verified via live search before asserting. Project conventions and captured decisions get recalled from the vault (and the FILE gets re-read before quoting; memories age too).
10. **A review with no findings must say what it tried.** A silent "looks good" is indistinguishable from a lazy pass — for every lens that found nothing, state the attack attempted.
11. **A cheap proxy flatters — treat its result as an upper bound, not a verdict.** A validation that omits real-world frictions (costs, real fills, latency, load, live data) systematically over-states success; the same test with the frictions in can flip a "win" into a loss. Model the frictions or label the result a ceiling. (Scar: bar-model, zero-commission backtests showed strategies "profitable" that real-tick + commissions turned into losses.)
12. **The winner of a hunt is upward-biased — confirm it out-of-sample before believing it.** Pick the best of N tried options and the survivor is the max of N noisy draws: it looks good partly by luck even if none has a real edge, and the more you tried, the weaker the prior that the winner is genuine. Discount the headline number and re-test the winner on data/conditions it was NOT selected on. (Scar: one config was the best of ~13 tried; its result was selection-inflated.)
13. **Prove behaviour-preservation mechanically, don't assert it.** When a change "shouldn't alter behaviour" (refactor, hardening, safety fix), run the before and after over the same fixed input and show a **golden-output diff** — byte-for-byte identical output. "It's neutral" is a claim; a zero-diff is proof. (Scar: safety fixes were confirmed to change nothing by reproducing a 2,337-line golden output exactly, twice.)
14. **Review the fix, not just the original — and in critical code, don't over-fix.** A fix is new code that can carry new bugs: run the verification pass over the FIX too (a second pass caught 6 issues the first couldn't, one a real gap). Converse: in safety / money / irreversible code an unnecessary change is itself a risk — leave a benign, self-healing finding documented rather than churn it.
15. **A small green sample proves the machinery runs, not that it works.** A few passing results confirm plumbing (it executes, wires up, logs) — never merit (correct / valuable / profitable at scale). Separate "does it run?" (fast, cheap) from "does it work?" (slow, needs volume and varied conditions); never let an encouraging first sample trigger a scale-up or a go-live.

## Two rules from the 2026-07-26 hub-wayfinding review (both PORTABLE:yes)

**V-D#N — A conditional-existence requirement must be enforced at EVERY site that emits the conditional thing.** A spec said *"link only if the target exists — derive it, don't hardcode."* The builder complied at one tier; the sibling tier emitting the **same** URL got no gate at all, though the existence data was already fetched two lines above the render. The corpus happened to be 100% valid, so every gate passed green and the asymmetry was invisible. *Apply:* enumerate every call site that emits that URL and check each one's gate independently — **a green corpus proves today, not the rule.** One gated site plus one ungated site is the finding, even at zero current 404s. *(first seen: sabaifly · hub-wayfinding build review · 2026-07-26)*

**V-D#N+1 — An automated "dismiss the blocker" step is itself a page mutation.** A reviewer's cookie-banner dismissal loop matched `/accept|ok|agree/i` across all buttons; `"ok"` matched inside an FAQ accordion label, so the loop **clicked an accordion**, expanded it, and shifted the layout. The next geometry A/B then reported a 5px regression that did not exist — ~30 seconds from filing a false MAJOR against a known pre-existing bug. A clean reload showed delta 0.00px. *Apply:* anchor dismissal selectors to the overlay's own container or exact button text (`^…$`), never a loose substring over every button; and take any layout measurement from a **fresh, untouched load**, then A/B once more to confirm. *(first seen: sabaifly · hub-wayfinding build review · 2026-07-26)*

## Four more from the 2026-07-26 nav-back-path rounds

**V-D — A predicate written for A→B is VACUOUS when evaluated from inside B.** A brief said *"reuse the existence check that shipped on the other side."* That check asked *"does B exist?"* from A; re-asked from inside B it is always true — silently converting a conditional link into an unconditional one that would have 404'd on **90% of pages**. It reads identical to a gated version in review and in a green sample. *Apply:* when a spec says "reuse the check from X", verify the DIRECTION. Name the exact resolver for the new call site and **prove it returns false somewhere**. *(first seen: sabaifly · nav-back-path brief review · 2026-07-26)*

**V-D — A link-existence predicate must test the set the HANDLER serves, not the primary data store.** "Link only if a hub exists" used the hub table, but the route also serves a static-guide fallback, so the real 200-set was a **union** — two valid targets would have been silently under-linked, and the repo already had the union built one file away. *Apply:* read the handler to the end; every fallback branch widens the set. Grep for an existing union helper before writing a predicate. *(first seen: sabaifly · 2026-07-26)*

**V-D — Pair every "appears N times" assertion with the same measurement where it must be 0.** A gate counted a phrase in the payload; the i18n message template and an unrelated key both shipped that text, so a page with **no link at all** returned a count of 2. A non-zero zero-case means the pattern is matching something other than the rendered element. *Apply:* assert on the parsed element (`querySelectorAll('a[href=…]')`), and always run the negative case. *(first seen: sabaifly · 2026-07-26)*

**V-D — Never round a test suite to N/N.** A build note claimed "1459/1459 green"; the reviewer measured 1439/1459. The 20 failures were pre-existing and identical on trunk — but a rounded-up number is indistinguishable from one hiding a real regression, and when two environments disagree the *discrepancy itself* is the finding. *Apply:* report the measured pair **plus the same measurement on the baseline branch**. "20 failed, identical on trunk" is a stronger claim than "all green" and costs one command. *(first seen: sabaifly · 2026-07-26)*

**V-D (generalise) — Adding a new item KIND to a collection corrupts every aggregate derived from it.** Slotting a link into a nav's `sections` array would have broken four invariants — a progress denominator that could never reach 100% (the exact bug that component's header said it was built to avoid), the initial-active seed, an index-range sweep, and a length guard. *Apply:* before extending a list with a new kind, grep every read of `list.length`, `list[0]`, `indexOf/findIndex`. If any aggregate treats members as homogeneous, the new kind needs its **own prop**, not a slot. *(first seen: sabaifly · 2026-07-26)*

**V-D (generalise) — Two hierarchy levels resolved by independent predicates can collide.** A city-state resolved the *country* rung and the *city* rung to the **same node**, emitting a duplicated breadcrumb — identical label AND identical href — in both the UI and the JSON-LD ladder. A truth table over {resolves, doesn't} has no cell for *"both resolve to the same thing."* *Apply:* when a case table is built from N independent booleans, also enumerate the IDENTITY cases (`level_i === level_j`). Assert **distinctness**, not just presence. *(first seen: sabaifly · 2026-07-26)*

## Seven from the 2026-07-26 three-lane night (brief loops + build panels + fix rounds)

**V-D — A review is theatre unless the reviewed version is the one the executor can read.** Round-N rework landed on trunk; the builder's dedicated worktree — named IN the brief — was still pinned pre-rework, so the builder would have executed the REJECTED draft, which looks complete. Docs-only divergence: no test, gate, or conformance check can see it. *Apply:* any revised artifact-plus-checkout pair (brief, skill, rubric, pack) gets a step-0 fast-forward AND a version self-assert the executor pastes as a receipt ("Status line must say vN; if not, STOP"). *(first seen: sabaifly · three-lane briefs round 2 · 2026-07-26)*

**V-D — A fix that supplies a FLOOR can delete the CEILING the feature depended on.** Adopting a reviewer's "≥17px" threshold cut the old "sized to the fade" rule; the goal sentence survived with nothing entailing it (17px padding + 32px fade = failure of the brief's own gate). *Apply:* when a rework replaces a sized/derived quantity with a threshold, diff the OLD text for every purpose the quantity served and re-satisfy each; prefer ONE derived number with all rationales stated at its definition. *(first seen: sabaifly · strip-fade brief v2 · 2026-07-26)*

**V-D — A deny-control that shares a short-circuit with an earlier predicate proves nothing.** Testing an allowlist exclusion with an `http://` probe rejects on the https clause in BOTH worlds (`!isHttps || !isAllowlisted`). *Apply:* enumerate every predicate that can reject the input; vary ONLY the property under test with all others held at passing values; require add→ACCEPT→remove→REJECT plus a positive-presence probe. The non-vacuity rule applies to CONTROLS, not just gates. *(first seen: sabaifly · sapporo fire-note v2 · 2026-07-26)*

**V-D — A blocking gate needs its OWN standing non-vacuity floor.** A scanner with a bare try/catch prints its all-clear and exits 0 having scanned ZERO files (missing dir, throwing stat). The mutate→fail→restore control proves it CAN fire today; only a printed denominator + a floored minimum + propagated errors prove it is still LOOKING tomorrow. *Apply:* every gate prints "Scanned N across M roots" and refuses to pass below a calibrated N. *(first seen: sabaifly · check-i18n build panel · 2026-07-26)*

**V-D — Verify an exclusion's complement as a PATTERN DOMAIN, not today's file set.** "Exactly 4 files revoked" was true and still hid three constructed holes: the regex's domain (any depth, both roots) exceeded the compensating control's domain (one root, depth 1) — plus written safety claims stating the opposite. *Apply:* make the exclusion and its compensating control coincide BY CONSTRUCTION (anchor the pattern to the control's exact root; make the control recursive over the exclusion's domain); test constructed FUTURE paths on both separator forms. *(first seen: sabaifly · check-i18n build panel, 4th allowlist-complement instance · 2026-07-26)*

**V-D — Relay multi-instance findings VERBATIM; counts invite instance-counting.** Told "4 superlative drops + 2 noun/tense fixes", a fixer delivered 4 plausible instances and 2 plausible fixes that were NOT the reviewer's — 2 of 5 sub-items unfixed, invisible until re-diffed. *Apply:* dispatch each sub-item verbatim (string, location, replacement, per-item DENY probe) and require a per-sub-item table back, never a count. *(first seen: sabaifly · sapporo residual round · 2026-07-26)*

**V-D — "I added an assert" is a done-claim: verify existence AND firing, per layer.** A delta note reported three machine-asserts an aborted edit script never wrote; every visible receipt passed because the CONTENT layer was genuinely clean — the guard-rail layer was absent. *Apply:* an assert/gate/test claim carries two receipts: its own string grepped in the committed file, and a mutate that makes it fire. Multi-step edit scripts leave a PREFIX on abort — verify each insertion. *(first seen: sabaifly · sapporo fix round self-catch · 2026-07-26)*

## Two from the 2026-07-26 overnight brief loop (flight-CTA v1)

**V-D — An inclusion gate and its apparent complementary exclusion are equivalent only while the value domain is two-valued.** A gate scoped `x === A` guarding a render dispatched on `x !== B` — the corpus held exactly {A, B}, so every gate ran green while a documented third value would render ungated. A two-valued corpus makes a scope divergence indistinguishable from correctness. *Apply:* when a gate guards a render, copy the renderer's predicate VERBATIM; if inverting, enumerate the value's declared domain (grep types/docs for a third value) and prove the predicates partition it. *(first seen: sabaifly · flight-CTA brief review M1 · 2026-07-26)*

**V-D — Run a spec's example implementation against that same spec's acceptance criteria.** A brief's normative snippet used nullish-`??` while the brief's own test list required empty-string fall-through; executing the snippet against the spec's case returned `""` where the spec demanded the next candidate. Illustrative code drifts from the criteria it illustrates — and executors are told to use named code verbatim. *Apply:* execute every normative snippet in a brief/spec against that document's own stated cases before it ships (authoring time AND review time — a node one-liner). *(first seen: sabaifly · flight-CTA brief review M2 · 2026-07-26)*

**V-D — A minimum-clearance assertion inside a scrollable container is unsatisfiable at the scroll extremes whenever the required clearance exceeds the container's own padding on that side.** A "≥32px inside both edges" focus invariant met a 16px-padded scroller: scrollTo clamps, so the first/last members could never reach the band and the mandated trace failed at step 1 — the executor's options were flail or loosen the assert. *Apply:* compare N against the container's padding before writing the assert; if N > padding, the invariant is "clear, OR clamped at the extreme" — and check whether the edge affordance being cleared is itself off at the extreme (usually yes: nothing is obscured). *(first seen: sabaifly · keyboard-reach brief review B-2 · 2026-07-26)*

## Three from the 2026-07-26 UAE card-verify pass

**V-D — A rendered-page absence check is invalid until the page is fully materialised.** An in-browser quote check scored 4 verified cards ABSENT; the page lazy-loads on scroll (body text 1,682 → 8,634 chars after scrolling to bottom). *Apply:* after navigate, scroll to bottom + settle BEFORE asserting absence, and prove the probe works with a positive control term known to be on the page. *(first seen: sabaifly · UAE verify · 2026-07-26)*

**V-D — A normalisation fallback must re-normalise whitespace after every character-class substitution.** Tag-stripping injects a space before punctuation, so a punctuation-insensitive fuzzy pass STILL false-zeroed on the double space — two live quotes briefly misread as missing. Same artefact class hits PDF extraction across page breaks. *Apply:* replace punctuation with a space THEN re-collapse whitespace; only then compare. *(first seen: sabaifly · UAE verify · 2026-07-26)*

**V-D — A citation can be textually verifiable and simultaneously VOID.** A government PDF's quotes verified verbatim in the archive while the publisher 404'd the document — "quote checks out" and "authority still stands behind it" came apart; a sibling card's live page now states the OPPOSITE guidance. *Apply:* treat publisher-withdrawal as its own HOLD class, distinct from quote-drift; an archive proves what WAS said, never what holds; hold every card sharing the dead source as a cluster and queue a live re-gather. *(first seen: sabaifly · UAE verify, Hayakum PDF + Ramadan card · 2026-07-26)*

## Two from the 2026-07-26 keyboard-reach build review

**V-D — In a mandatory scroll-snap container, a programmatic scroll target is a request, not a command.** The browser rejected minimal-delta targets and settled at sparse snap points — 3 reachable rest positions for 7 items, measured identically by builder and reviewer via direct-assignment sweeps. The necessary escalation net then carried its own bugs: a stale direction variable and an unbounded hard-extreme jump that overshoots the band whenever remaining travel exceeds the container width. *Apply:* enumerate ACTUALLY reachable rest points by direct assignment (never smooth-scroll timing); re-check after settle; escalate in bounded steps with re-checks, hard extreme only as last resort. *(first seen: sabaifly · keyboard-reach build · 2026-07-26)*

**V-D — A runtime proof is only evidence about the build the server is actually serving.** A reviewer's spec run against worktree A silently attached (reuseExistingServer) to a pre-existing dev server serving the MAIN repo — producing a confident, entirely false "2 failed" for code that was never loaded; the failure text was byte-identical to the expected mutate-control reds, maximising the trap's credibility. *Apply:* before believing any runtime pass/fail, identify the process serving the port (PID → command line → working directory) and confirm it is the checkout under review, or force a fresh server on a private per-review port. *(first seen: sabaifly · keyboard-reach build review · 2026-07-26)*

## Three from the 2026-07-26 D4 accessibility claim-verify

**V-D — An absence verdict on decoded text is void until the decoder is proven correct.** An HTTP-200 page decoded as mojibake scored 4 genuinely-present quotes ABSENT; re-decoding with the right legacy codec found all 4 verbatim. *Apply:* on non-English/legacy pages, select the encoding by maximising target-script character yield, and set a script-character floor below which absence results are void. *(first seen: sabaifly · D4 verify, MLIT Shift_JIS · 2026-07-26)*

**V-D — Text matching needs three tiers, because extraction splits words as well as joining them.** PDF/HTML extraction injected spaces INSIDE words ("publi c facilities"); the two-tier fallback (exact, punct-insensitive with whitespace recollapsed) still missed 4 present quotes. *Apply:* add the third tier — strip ALL whitespace on both sides and compare — before any absence verdict. *(first seen: sabaifly · D4 verify · 2026-07-26)*

**V-D — A tool-level fetch failure is evidence about the tool, not the source.** Sources recorded "robots-blocked/unverifiable" opened cleanly in a real browser (one then FALSIFIED a stale claim the gather had carried; another had no robots.txt at all) — while a nominally reachable source redirected a live browser to adware. *Apply:* escalate every 403/blocked verdict through UA-fetch then real browser before recording BLOCKED, note which transport failed; separately verify reachable sources are SAFE — reachability and trustworthiness are independent axes. *(first seen: sabaifly · D4 verify · 2026-07-26)*

## Two from the 2026-07-26 Dubai card-verify

**V-D — A redirect-to-root is a soft-404 that masquerades as success.** A dead asset URL 302'd to the homepage with a 200 final status — reading as a successful fetch with the quote merely "absent"; the truth (host-wide block, document alive on a migrated host) was only reachable via a control request for an unrelated sibling asset that failed identically. *Apply:* on quote-absence over an asset URL, compare FINAL url to requested url before any withdrawal verdict; then probe an unrelated sibling on the same host — identical failure means host-level, not document-level, and the asset is probably re-homed, not gone. *(first seen: sabaifly · Dubai verify, dm.gov.ae → dmpmedia migration · 2026-07-26)*

**V-D — Before treating a deeper URL as a stronger citation, prove the server discriminates paths.** Two sites returned HTTP 200 *with the sought quote* for every path including a deliberately bogus one — a deep-page re-cite there manufactures a citation to a page that does not exist. *Apply:* request a deliberately nonexistent sibling path; only trust the deep cite if the bogus one 404s and lacks the quote. *(first seen: sabaifly · Dubai verify, Burj Al Arab SPA · 2026-07-26)*

## Five from the 2026-07-26 Maldives card-verify

**V-D — A live 200 at the cited address proves the address resolves, never that it still serves the document you cited.** Reachability and redirect checks both passed while a superseding document sat under the same URL (re-issued for new legislation); only the quote assert caught it. **V-D — A positive control only licenses an absence verdict for text of its own structural class.** A prose control ("Hanifaru" found) said nothing about whether all-caps infographic signage was extractable — the exact class of the missing strings; a same-class control (count all-caps runs) made the verdict sound. *Apply:* before declaring a string missing, prove the extractor finds a string of the same kind — same casing, same container, same encoding path. *(first seen: sabaifly · Maldives verify · 2026-07-26)*

**V-D — Restoring detail a summary dropped is an ADDITION, not a correction.** Three restorations were right; one restored a grouping the source never had (an item placed into a list that lives elsewhere on the page). **V-D (generalise) — Escalating the CLIENT and varying the ADDRESS FORM are different probes.** http://apex 500'd and was recorded as "non-TLS source, expect friction"; https://www was a clean 200 with a discriminating 404 control — a single vhost's misconfiguration mistaken for the host's capability. *Apply:* before recording a host as lacking a capability, probe the {http,https} × {apex,www} matrix; transport escalation never varies the URL form. *(first seen: sabaifly · Maldives verify, maafushi.gov.mv · 2026-07-26)*

## One from the 2026-07-27 sapporo prose-photo review

**V-D (generalise) — When the framework enforces one dev server per checkout and the running one is not yours to kill, a DATA-ONLY change can be runtime-proven on the shared server IFF the negative control is a live data mutation observed end-to-end (mutate → served output flips → restore byte-identically → re-fetch green).** The observed flip proves the server reads the working tree through the real render path, substituting for server freshness. A CODE change cannot borrow this — it still needs an isolated checkout with its own server. *(first seen: sabaifly · sapporo chapter-photos V-Kai review, Next.js 16 single-dev-server lock · 2026-07-27)*

**V-D (generalise) — A case-insensitive fixed-string probe can FALSE-ZERO on non-ASCII bytes: case-folding under the default locale bails on UTF-8 content and returns 0 while the string is present.** A deny-gate that can false-zero converts a leak into a recorded green. *Apply:* deny-probes over raw served bytes run under a bytewise locale (LC_ALL=C) with fixed-string matching and NO case-folding (enumerate case variants explicitly), and every deny-probe pairs with a positive-presence control in the same run. *(first seen: sabaifly · UAE hub redteam lens C, Git Bash grep -i -F on ℃/em-dash bytes · 2026-07-27)*

  text fields" captures fields verbatim-copied from an upstream authority; the glob then authorises
  overwriting a controlled value. For each in-scope field ask: copied, or composed here? Copied goes
  OUT with the cap named. *(brief B1)*
- **If a work order adds to something a check measures, it carries the check's limits and the current
  reading.** "Add X" against an unquoted budget is an order to fail the check — state band, current
  measurement, headroom, and net-add vs net-cut. *(brief B2)*
- **An analysis may not assert a field its instrument does not emit.** Read the extractor's output
  schema first; anything richer in the write-up is inference, and the inference fails precisely on
  the anomalous rows. Mirror image also holds: don't conclude "unresolvable" from an instrument that
  dropped the disambiguating field. *(probe B3 + residual R1)*
- **A section admitted fabricated is regenerated from source, never revised in place** — the
  replacement inherits the fabrication's structure and its invented particulars. Self-disclosure
  raises the review bar; it never discharges it. *(probe placeholder)*
- **Commentary next to a machine-read field is not evidence of its value.** Verify structured fields
  by reading the field, then reconcile every prose claim about it — including summaries written
  elsewhere. *(Qatar field B2)*
- **When the same claim is stated in more than one place, verify each statement separately.** Audits
  that map claims rather than occurrences report full coverage while the weakest-hedged restatement
  goes unchecked. Index by sentence instance; grep for the twins. *(exemplar FIX-1/FIX-2)*
- **A newly identified risk class in one item of a batch is a search order over the whole batch.**
  Per-item review structurally cannot catch it — each item is internally consistent; only a
  cross-item sweep for the named class will. *(C4 F1: OTA-evidence risk carded in one pack,
  instantiated in its sibling)*

## Promoted 2026-08-09 (first seen: sabaifly · ONESTOP-RETROFIT arc)

- **Field contract transcribed, not paraphrased.** A work order that populates a declared field
  must carry the field's contract verbatim — including its exclusion clauses — and be dry-run
  against one real in-scope instance; a paraphrase that keeps the positive half and drops the
  exclusion produces valid-looking wrong data that every downstream gate passes.
- **Where a record is filed is not what it says.** A claim about a relation between two entities
  needs both entities named in the evidence itself; a folder, id or section heading that supplies
  the missing one is the reviewer's inference, not the source's. And once a batch has rejected on
  a ground, that ground binds every unit in the batch — consistency outranks any single inclusion.
- **A provenance sweep grades premises, not citations.** A sweep that grades only the source you
  cited misses the grade of the premises that source silently borrows. Enumerate the load-bearing
  premises first; an entry is no stronger than its weakest premise, wherever that premise lives.
- **A count written into a comment is a claim nothing verifies.** Assert it (derive from the
  corpus at runtime) or delete it — and when you change a population, grep for the comments that
  count it.

## Promoted 2026-08-09 (second batch — voice-arc arc)

- **When a work order excludes an item and gives a reason, verify the reason against the source**
  — a lock with a false rationale hides in-scope work behind an unexamined premise. (Exclusion-layer
  sibling of field-contract-transcribed-not-paraphrased.)
- **De-first-personing a sentence does not de-jargon it.** Sweep internal vocabulary as a named
  token lexicon over the whole batch, and check whether any internal term is a homonym of a domain
  term — there it reads as a false domain claim (read affirmative sentences aloud, not only
  negations).
- **Name capture artifacts by the full identifier of what they capture** — a colliding shorthand
  silently replaces one measurement with another; an unexpected zero on a positive-presence probe
  is a probe-integrity question before it is a content conclusion.

## Promoted 2026-08-10 (security-injection brief)

- **Before proposing "compute it on the server and hand the client a signed/validated value,"
  verify the value isn't a function of interactive client state** (`useState`/`useMemo` keyed on
  user input). If it is, server precomputation can't work without a per-interaction round trip —
  the fix must change. (first seen: sabaifly · feedback_brief_signing_fork_ignored_interactive_client_state · 2026-08-10)
- **Scope a crypto binding to the values that actually escape existing validation, not to every
  value a shared helper emits.** Ask "which values bypass the allowlist/validation today?" — often
  it's one; binding the rest protects paths the allowlist already covers while importing new
  problems (e.g. a client caller that can't hold the secret). The cheapest fix that closes the
  *confirmed* hole wins: a disabled/unemitted bypass branch is closed by deleting the branch, not
  by adding a secret or a DB lookup to the hot path.

## Promoted 2026-08-10 (RAG data-fence brief, 3A.3)

- **A random/nonce delimiter fence protects untrusted content only if the random token is required
  to CLOSE the fence, not just open it.** A static closing delimiter (`</tag>`) is guessable, so
  attacker-controlled content can forge it and break out — the unguessable opening nonce buys
  nothing. Put the nonce in BOTH delimiters (`[[CTX:a1b2c3]]…[[/CTX:a1b2c3]]`) and/or strip the
  delimiter token from the fenced content; the non-vacuity test must feed a literal forged closing
  delimiter and assert it stays fenced-as-data. (first seen: sabaifly · feedback_nonce_fence_guessable_closing_delimiter · 2026-08-10)

## Promoted 2026-08-10 (rate-limit build 3A.2 + the cleared 07-29 limiter debt)

- **A negative/mutation control must confirm the target check actually EXECUTED and produced the
  expected failure.** A check that was filtered out, skipped, or not-run is indistinguishable from
  one that ran and passed, and proves nothing. Assert "ran AND failed", never "no failure observed"
  — read the explicit failed-count and the failing test name. (Test-runner name-filters are often
  REGEXes: literal parens/brackets/dots in a title silently match nothing → "N skipped".) (first seen: sabaifly · feedback_mutate_control_skipped_not_passed · 2026-08-10)

### Limiter/denial-of-wallet trio (first seen: sabaifly · limiter-brief-review-lessons · 2026-07-29; promoted 2026-08-10 at the 3A.2 merge harvest)
- **A finder's/report's fixPlan inherits NO verification from a lane's CONFIRMED.** A design lifted
  from an investigation report's recommendation section is an UNREVIEWED new proposal — attack its
  security/abuse complement fresh; a "root cause CONFIRMED" verdict covers the findings re-derived,
  not the fixes proposed.
- **A relay bypass reopens the external surface.** "Internal caller" ≠ "trusted" when the component
  relays externally-originated input. Never key a rate limit / trust-exemption on a relay's
  identity; key on the ORIGINATING client or a global budget, and make any internal marker
  non-spoofable.
- **Every limiter re-key answers, in writing, WHO controls how many distinct key values exist.** A
  caller-mintable key (resource ids, arbitrary emails, rotatable fingerprints) converts a bounded
  budget into an attacker-controlled multiplier. Per-resource keys may only be AND-ed WITH a
  per-client and/or cardinality-1 global budget — never substituted for one. (The narrowed-allowlist
  "verify the complement" law, specialised to limiter keys.)

## Promoted 2026-08-10 (observability brief 3A.4)

- **A pass/fail monitor wrapped around code that catches its own errors and returns an error value
  records SUCCESS on every handled failure.** Wrapping only flags never-ran (missed) and uncaught
  crashes — it is blind to any failure the handler converts to a returned status/value (HTTP 500,
  {ok:false}, a sentinel). Before wrapping, check whether the code throws or catches-and-returns; if
  the latter, have the wrapper inspect the returned result and set the check-in status manually, or
  document that the health signal covers only never-ran + hard-crash. Adjacent: start the monitored
  region AFTER any early-return auth gate (a 401 else resolves "ok"), and code-side upsert-on-first-
  check-in does not cover a job that never fires from launch (pre-create the monitor). (first seen: sabaifly · feedback_monitor_wraps_catching_handler_false_ok · 2026-08-10)

## Promoted 2026-08-10 (mirror-map widen brief)

- **A word-boundary matcher does NOT neutralize a token that is a whole common word — only tokens
  embedded in longer strings.** Classifying a bare-token lexicon add as "safe because the matcher
  is `\b`-bounded not substring" is an error for whole-word homonyms (`\bcondor\b` fires on the
  bird). Classify each bare-token add as unique / whole-word-homonym / substring-of-longer; word-
  boundary defends only the last. For a whole-word homonym, the disposition is the fail-closed /
  out-of-register precedent, NEVER scoping to a longer form the real input never uses (that revokes
  the coverage the add exists for). And never require a "does-not-match" done-proof the matcher's
  own semantics make unsatisfiable — verify the matcher CAN satisfy the proof before demanding it.
  (first seen: sabaifly · feedback_word_boundary_homonym_token · 2026-08-10)

## Promoted 2026-08-10 (queue-brief V-Kai reviews — volatile gate + blog notFound)

- **A brief that runs a command in a fresh isolated workspace must provision the untracked files
  that command depends on; a green pipeline proves nothing about a command the pipeline never
  executes.** Untracked prerequisites (env files, local caches, credentials) do not follow a
  worktree/clone; state how each reaches the workspace, name the platform traps, and never cite
  CI-green as evidence for a command CI never runs — a first failure there is a recordable finding,
  not a stub-and-continue. (first seen: sabaifly · feedback_worktree_brief_provisions_untracked_prereqs · 2026-08-10)

- **When a gate detects compliance by searching for a marker string, restrict the search to fields
  that can legitimately carry the marker and exclude audit/review/verdict fields** — reviewer text
  quoting or demanding the marker ("this record lacks an ELIDE marker…") will otherwise satisfy the
  search on precisely the non-compliant records. Mandatory fixture: marker present ONLY in the
  verdict/audit field → gate still FAILS, record id asserted. The audit trail necessarily names the
  compliance token while discussing its absence; any detector that can see the audit trail is
  satisfied by the complaint about the violation. (first seen: sabaifly · feedback_marker_search_matches_audit_trail · 2026-08-10)

- **A gate proven only to fail is not proven to work: pair every must-fail control with a must-pass
  fixture through the same entry point, or an unpassable gate ships undetected and gets overridden
  instead of fixed.** Must-fail mutate controls prove the gate can CATCH; only an end-to-end PASS
  scenario (same entry point CI invokes, clean corpus → exit 0 + the all-clear output asserted)
  proves it can CLEAR. One limb without the other carries no information in that direction.
  (first seen: sabaifly · feedback_gate_pass_path_untested · 2026-08-10)

- **A runtime review executed in the builder's own workspace verifies the code, not the checkout —
  materialization-dependent defects (line endings, path length, case) are invisible there and
  surface only on a differently-materialized checkout.** The merged-tree gate is the first such
  place; never waive it because the branch was "already runtime-reviewed" — those reviews ran on an
  inherited filesystem realization. When a merge-gate failure contradicts a green branch review,
  suspect materialization FIRST: compare ON-DISK bytes (git diff silence is not byte-identity
  across checkouts), then pin the sensitive class (e.g. .gitattributes eol rules) the first time it
  bites. (first seen: sabaifly · feedback_merge_gate_catches_materialization_defects · 2026-08-10)

## Existence probes cover CREATION targets (first seen: sabaifly · BRIEF-I-KAI-E2E-READINESS-PROBE review · 2026-08-17)

When a brief claims a file will be NEW, probe that path too — an existing file at the creation
target (especially one with early-return guards) silently converts "create" into "extend before
the guards", and the natural append placement can no-op the feature precisely where it must fire.
The probe's job is to force that discovery at brief-writing time, not mid-build.

## Change-every-occurrence briefs carry the fresh-sweep predicate (first seen: sabaifly · BRIEF-I-KAI-PRICING-ALIGNMENT review · 2026-08-17)

Any change-every-occurrence task in a brief must include the exhaustive search command that
produced the occurrence list — scope, predicate, and a read-each-hit instruction (grep counts
lie) — and instruct the build to RE-RUN it. A list recalled from a prior audit under-enumerates
and re-creates the surviving-instance defect the task exists to fix.

## Empty-string env overrides are shell-dependent (first seen: sabaifly · e2e-readiness-probe build review · 2026-08-17)

Setting an environment variable to the empty string means "present and empty" in POSIX shells but
"deleted" in PowerShell and cmd; any test that depends on an empty-var override (e.g. blocking
dotenv's no-override re-population of a secret) must verify the variable's actual runtime value
after ALL env-loading layers, in the shell actually used — one `node -e` printing
JSON.stringify of the var. Never infer the env shape from the command line alone.

## A mutate-control is unverified until the mutation is proven visible to the runner (first seen: sabaifly · pricing-build panel · 2026-08-17)

A mutate-and-test control proves nothing until the mutation is proven visible to the test runner —
verify the mutated bytes via the runner's filesystem and clear any transform/module cache first
(vite/jest/webpack caches can serve the unmutated module). An unexpectedly green control means
EITHER vacuous tests OR a masked mutation; the two must be distinguished before either is reported.

## "Every hit dispositioned" is verified by set-diff against a fresh predicate run (first seen: sabaifly · pricing-build panel · 2026-08-17)

An "every hit dispositioned" claim is verified by set-diffing the disposition list against a fresh
run of the same search predicate — a hit absent from both the changed and the deliberately-untouched
columns is an undispositioned miss, even if dead code.

## A mutate-control makes an agent a WRITER (first seen: sabaifly · pricing-build panel dispatch · 2026-08-17)

When multiple verifiers share one working copy, any verifier's mutate-then-restore control can
interleave with another verifier's test run — false failures for one, vacuous controls for the
other. At dispatch: count every agent whose method includes a mutate-control as a WRITER; serialize
mutation windows or isolate checkouts; every verifier brackets each run with a cleanliness check
whose violations invalidate the run in both directions.

## A deny-gate is only as real as its predicate (first seen: sabaifly · public-pack brief review · 2026-08-18)

Every denylist entry ships as a runnable pattern; path/name tokens enumerate EVERY encoding
(backslash, forward-slash, slug/encoded, hyphenated); the positive-presence control plants each
VARIANT, not just the canonical form; and any non-greppable category entry gets a literal-token
enumeration for the scripted limb plus an explicit human/LLM read-pass limb — otherwise the
scripted limb is vacuous precisely on the entries that matter most. Proven the hard way: a banned
machine path's slug encoding was already live on a public repo while the canonical-form grep passed.

## A public-repo scrub gate covers HISTORY, refs, and audit text — not just the tree (first seen: sabaifly · public-pack confirmatory · 2026-08-18)

A content-scrub gate on a publicly-visible repo must cover every public surface: commit history,
every pushed ref, and PR/issue/audit text — not just the final tree. Scrub before first commit,
keep planted gate-controls out of commits, run the deny-predicates over the full history diff
before any push, and write audit notes naming banned tokens by role, never by value.
